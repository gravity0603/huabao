# 成品与事实记录

## 四项题卡

普通批量创作直接给成品，默认仅显示：

```text
1. 标题：限长、对象/场景明确、一个具体好奇点
副标题：补事实细节或必要条件，不重复标题
内容摘要：一个自然段，实际看点→原文论据/案例→解释及必要边界
相关信息链接：[来源名·实际文章标题](https://真实正文链接)
```

标题旅行/萌宠≤7字符，其余≤10；副标题≤25，标点等计数。没有指定时摘要可约100–180字，简单事实更短，用户要求优先。摘要不是“内容方向”，不能只写聚焦/盘点/值得一看。旅行必要时补地点，合集逐案例给事实和来源；链接数量以能支持事实为准。

**图片由用户人工复核，不默认交图片包、逐图检查表、尺寸/构图/授权结果或图片核验缺项。** 无需为每批重复版权提示。仅在用户要配图方向时简短给对象/场景关键词，不能声称图片已审。

草案中事实、时效、舆情或近期去重有具体缺口时定位到对应题；核心事实缺证据放单独“待验证线索”，不混入已核实题卡凑数。数量不够就如实交已完成数量与缺口。

## 文章与批量改稿

文章依据已给/已核事实，优先总分结构；先交代看得见的现象再解释机制，避免生硬总结式结尾。严格执行指定总字数、段数及段长。没有明确字数不自行套所有题700字。

批量副标题提供不同信息角度和句式的可直接选用版本，不把同一句换一两个词当多个版本。主标题有疑問必须带问号；锁屏文案若另有任务，按其实际字段和规范检查，不能把内部摘要当入口文案。

## 内部保留，默认不外显

记录对象/作品/地点身份、核心事实/机制、标题、副标题、摘要；每条主张与实际打开来源的映射；来源原名/标题/URL、文章与事件日期（可确认时）、读取日与限制；历史/近期/本批比较范围与概念碰撞。

当前对话可保留内部事实/概念比较记录，不为每次聊天强制生成文件。用户要求维护选题记录、跨批生产或交付文件时，在用户工作目录保存；已有记录则沿用。区分候选、选用、已制作、否决，不能把本助手推荐写成已制作。不修改原始CSV或用户记忆。

事实核验完成不等于图片复核或平台审核。用“选题草案”“待验证”“待补R复核”等准确状态；不因未做图片人工复核阻断选题，不擅自称可上架。用户问审核结果时只报告实际存在的证据。

## 可选JSON

无需为所有任务生成JSON。使用机械工具时结构如下：

```json
{
  "topics": [{
    "category": "旅行",
    "object": "真实对象/地点名称",
    "title": "最终标题",
    "subtitle": "副标题",
    "summary": "单段含事实论据的摘要",
    "concept_key": "对象|核心事实机制|切口",
    "sources": [{"id": "s1", "name": "机构名", "article_title": "实际原文标题", "url": "https://example.org/article", "opened": true}],
    "claims": [{"fact": "核心事实", "source_ids": ["s1"]}]
  }]
}
```

示例URL仅解释结构，不允许进入实际成品。`opened`是人工记录，脚本不会上网核实。无需image/rights字段，不让工具假装用户已人工复核图片。
