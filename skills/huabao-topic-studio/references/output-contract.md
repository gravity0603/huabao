# 四项输出与内部核验记录

## 默认题卡

```text
1. 标题：<限长且对象/看点明确>
副标题：<25字符以内，补充真实细节>
内容摘要：<一个自然段；具体对象和看点、来源论据或案例、解释/必要边界>
相关信息链接：
- [来源名·实际文章标题](https://...) — 支持的具体论据。
```

普通选题默认只交付上述四项。批次开头统一说明“以下为选题草案，图片精查与授权在选定后完成”，不每题重复制作缺项。具体事实、时效、去重的缺口仍逐题说明；用户要求配图或进入制作时，再补图片/核验状态，不把未查看写成已查看。

旅行补地点；明星盘点补至少4个案例，摘要可归纳共同看点，案例列逐个给“对象—对应事实—支持链接”。影视合集补具体作品及播出状态。补充字段是满足可写性的必要信息，不能挤掉四项核心字段。

一段有论据的摘要应能回答：说的是谁/什么？奇在哪里？哪条记录、数据、研究、场景或公开案例支持？为什么这能支撑标题？有什么重要条件？不能只写“聚焦XX，盘点XX，值得一看”。直接论据和编辑解读分清，别把情绪价值包装为科学结论。

同一链接支持多条事实可合并；合集各对象必须有支持，不强求每对象不同URL。一个页面确有4人相应事实，可以共同引用。不能用一人的页面替其他人背书。

## 状态规则

- **待验证**：核心信息未实证；仅作单独线索，说明缺什么。
- **待补R复核**：已有事实支持，近期选题范围未完整读取，语义去重尚缺。
- **待排期草案**：供编辑考虑；图片精查与授权可统一在批次说明后移到制作阶段。个别事实、舆情、时效、去重缺口逐题说明；只有触发规范更新且未完成时才列“最新规范待复核”。
- **已完成选题核验**：已逐项记录事实、图源、授权、去重、时效、品类风险和规范核对的结果。仍不代表平台实际审核通过，不自动标“可上架”。

## 需要保留的内部记录

每题记录对象、品类、概念族、标题及摘要；每个论据与source_id的映射；原文读取结果与日期；相关事件时间/适用季节；可配图判断和图片实际查看情况（未查看就如实记录），制作时再补授权依据；参考表、素材库、已做标题、近期记录和本批的去重范围及碰撞；品类风险、本地规范版本及缺项。正文默认不展示长审计表，需要审核/交接时提供。

跨批次在用户指定工作记录里保存事实/概念族和“候选、已选用、已制作、已淘汰”等真实阶段，不把推荐当已制作；未指定时可在本次输出目录保存`选题记录.json`。不要修改原始CSV或用户记忆。

## 可选JSON结构（供机械校验）

```json
{
  "topics": [{
    "category": "旅行",
    "title": "题名",
    "subtitle": "副标题",
    "summary": "含具体事实和解释的单段内容摘要",
    "sources": [{"id": "s1", "name": "来源名", "article_title": "原文标题", "url": "https://example.org/article", "opened": true}],
    "claims": [{"fact": "具体事实", "source_ids": ["s1"]}],
    "cases": [],
    "mode": "单题",
    "concept_key": "对象|核心机制|切口",
    "status": "待排期草案",
    "missing_checks": ["图片精查待制作阶段完成", "图片授权待确认"],
    "checks": {"facts": true, "image": false, "rights": false, "dedup": true, "timeliness": true, "category_risk": true, "policy": true}
  }]
}
```

示例域名只解释schema，不能进入真实交付。案例对象用`{"object":"姓名/剧名", "fact":"相关事实", "source_ids":["s1"]}`；明星默认按合集校验，单人专题用`mode: "单人专题"`且需任务确实指定。普通草案允许image/rights为false，不因此阻断选题交付；policy为true可指按所注明的本地规范筛查，不表示本批在线更新。`checks`只是人工填写的结果，脚本不会验证其真实性。
