# 华为画报选题工作室

## 目标与依据

交付能继续写稿和找图的具体选题。每题固定包含 **标题—副标题—一段含论据的内容摘要—相关信息链接**，不能用“内容方向”“一句空泛介绍”替代摘要。

本 skill 独立重建。流程依据是用户近期六个置顶 ChatGPT 选题对话、用户明确要求、各品类标题 CSV 和华为官方素材审核规范，不继承其他已安装选题 skills 的流程、术语、评分或脚本。

- 来源与读取范围见 [references/source-map.md](references/source-map.md)。对话是风格与反馈依据，历史 AI 回答不是事实来源。
- 使用本地 [references/huawei-review.md](references/huawei-review.md) 的已核实规范；普通找题不重开官网。仅用户要求更新规范、收到新审核反馈、已知规则变化或实际提审需要最新版时再打开官网。按本地规范筛查不是“本次在线复核”，也不因未重开官网给每批增加“最新规范待复核”。
- 按品类只读 [references/category-playbook.md](references/category-playbook.md) 的相关部分。
- 输出与证据记录见 [references/output-contract.md](references/output-contract.md)。
- 找题与标题打磨读 [references/research-and-headlines.md](references/research-and-headlines.md)，执行“对象发现→标题竞争→入选题核实”，不要让制作级查图挤占找题工作。

## 不可省略的约束

- 用中文，具体对象和单一看点优先；短、直观、有信息增量，有网感但不生硬玩梗。
- 旅行、萌宠标题≤7字符；其他品类≤10字符；副标题≤25字符。标点、引号、空格、数字和英文字母均计数。疑问句必须有问号。不得为压字数用难懂缩写或删除必要主体。
- 萌宠限定猫、狗，最多可含大熊猫；其他动物单列动物类。萌宠标题不用“它”作模糊主语。
- 全程排除日本相关地点、文化、品牌、IP、人物、图片与来源，以及日本中心的比较；这是用户工作偏好，不冒称华为平台条款。
- 未核实或争议信息准确标注“可能、据报道、尚待确认”等。标题也必须保留事实的不确定性，不能靠摘要小字纠正标题的错误定论。
- 有明显合规问题、核心事实不成立、无法兑现标题或完全没有可靠原文的候选，淘汰或放到单独的“待验证线索”，不混入已核实选题凑数。
- 不因脚本通过就宣称来源、授权、去重、舆情或平台审核通过；不自动发布、发送、购买授权或删除旧 skills。

## 规范流程

### 1. 读取输入，确定这批的边界

先读用户这次给的素材库、链接、图片、已做标题、近期选题和数据。素材库有时间时，从最新链接开始；无时间则说明按现有顺序。先利用素材库，再针对缺口上网补充，不能跳过素材库直接泛搜。

确定品类、数量、国内外比例、时间范围、季节、是否合集及特别限制。明确给出的数量和范围必须执行；没给时按任务合理选择并简短说明，不套固定配额。

读取 `D:\yiyouliao working\选题参考` 中对应 CSV。目录不可访问时使用本 skill 内 `references/title-samples` 的快照并说明日期；二者均缺失则报告缺口，不声称已对齐。CSV 用真实解析器，先尝试 UTF-8 BOM/UTF-8，失败再 GB18030，不用替换乱码方式“读完”。旅行补读《旅行类标题参考.csv》；明星补读《明星类标题参考.csv》。重复“标题”列都要读，空月份沿用上一条月份，空行忽略。

只提炼标题机制：对象、反差、动作、问题、细节、读者收益和副标题兑现方式。参考表可能有过长、夸张、错配、陈旧及不合规案例，不照搬句子，也不把历史选题里的事实当证据。无曝光数据时，不推断高曝光、CTR或转化效果。

### 2. 从对象和图像切口寻找候选

每个候选先写内部的一句定位：“什么对象，出现什么真实意外细节，图片怎样看出来，正文能解释什么”。优先一张图能认出对象/现象的题，也允许美观的主体图承接有证据的知识点，但不得把装饰图当现象证明。

按品类手册选择方向。热点请求核对事件发生时间与报道时间；老事件重发不算新热点。季节按当地实际物候和当前排期判断，不把当前月份机械套在所有地区。

可使用当前可用的ChatGPT、豆包、DeepSeek、Gemini等AI工具、连接器或已有登录浏览器辅助检索对象、反差和标题。根据可用性选合适的一种即可，无需全部调用，也不因AI工具不可用暂停任务。将对应品类风格、已做概念、数量范围和限长传给工具，索取具体对象、事实钩子、不同标题切口及原文线索。不要只索取泛泛的“热门选题”。AI返回是候选，不是事实证据；不能把工具自报“已检索”当作本助手已打开来源。具体使用与提示词见找题手册。

先发现一小批有真实反差的对象，并给有希望的对象拟不同风格的标题，淘汰平淡/重复题后，再集中核实入选对象；不对每个初筛候选做全文、图片和授权全套检查。别为完成内部流程生成额外大表或下载素材包。

### 3. 打开原文，形成证据

搜索结果只找线索，必须打开文章正文。每题至少有一个支持核心看点的可靠原文，摘要中每个关键数据、人物经历、剧情、技术条件都能对应来源。一个原文足够支撑时不强求链接数量；合集的各案例分别需要证据。

优先官方机构、研究机构/论文、作品与人物公开的一手资料、合规媒体。媒体转述追溯原始资料；商业产品资料可核实技术，不能直接照抄营销结论。海外一手科学资料可用于研究核实，正式转载的主体资质及署名另行核验。

保留来源名、原标题、实际 URL、发布日期/事件日期（能确定时）、读取日期、支持的具体事实与限制。打不开全文、只看到摘要、日期不明或相互矛盾的地方如实标明；不得拼接 URL、补造文章标题、用首页或搜索页冒充原文。

### 4. 判断可配图性与品类风险

普通选题阶段不要求逐张打开、下载或查看图片。根据可靠原文配图、图注、官方项目图库、检索预览或明确的摄影对象，判断“有图可找＋题眼能如何表现”，必要时给图源入口或找图关键词。未实际看图时写“配图方向/图源线索”，不能写“已看实拍/构图已核”。只有题眼依赖可疑视觉现象、照片真假/地点/对象存在冲突，或用户指定以某图出题时，针对关键图查看；用户要求图片交付、选定题目进入制作或提审时，才逐张核验对应性、规格、构图和授权。查图失败时换图源线索，不为普通找题多轮猜文件名、下载、裁切。

按本地已核实规范检查题材和配图方向。人物检查近期负面舆情；科技检查竞品与广告属性；车辆检查争议品牌、宣传倾向和适用条件；影视核实作品存在、播出状态、角色与剧情，不把演员生活当剧情。图片姿态、规格和授权等制作检查延后，不把“找题”和“已可发布”混淆。时效、危险操作、健康养宠或驾驶建议必须在论据中交代适用边界。

### 5. 去重并筛选

比对参考 CSV、素材库、已做标题、近期对话/选题记录及本批候选。内部登记“对象＋核心事实/机制＋读者收益/图像切口”。同一个事实换标题、同一概念族换地点/人物、同一作品同一桥段改话术都视为重复。确有新机制/新事件才考虑重做，并说明差异；默认优先换题。

读取范围不足时标明“近期选题记录未提供/未完整读取，待补R复核”，不宣称全面去重。跨批次记录保存至用户工作目录中的选题记录，不写进 skill 安装目录。普通使用更新工作记录不等于修改用户记忆。

事实与合规是底线，吸睛程度是候选筛选条件，两者同时满足。不能因事实正确就接受平淡的说明性标题；有论据却没有可讲的反差，优先换对象/切口。证据不足也换题，不以惊悚程度、营销话术或主观评分补救。批量时分散对象、机制、视角与句式，避免全批“XX会XX？”或同一词反复套用。

### 6. 写四项成品

初筛时先从事实钩子拟标题，核实后写摘要并回修标题；不要把百科摘要直接压缩成标题。内部给每个入选对象拟至少3个不同切口的标题，例如直观反差、生活场景错位、意外用途/能力；不是给同一句加不同引号。用找题手册的标题检查选出一个最有记忆点且能兑现的版本，默认只交付最终版，不让用户承担内部筛选。标题制造一个具体好奇点；副标题补对象、条件或具体细节，避免重复主标题；摘要一段讲清“实际看点→来源中的论据/案例→解释及必要边界”。摘要长度按用户要求；未指定时建议约100–180字，事实简单时可更短，不硬凑字数。

明星合集默认每题至少4个不同案例对象，逐个说明相关事实及来源，不能仅堆4个人名。用户明确指定单人专题时围绕本人，不硬塞4人。影视合集按用户数量列剧目，无指定时以可核实、共同主题明确的组合为准，不把待播剧装入“热播必看”。

默认按题卡输出四项。普通找题可在开头统一说明“本批为选题草案，图片精查及授权在选定后完成”，不必每题重复制作缺项；具体事实、时效或去重缺口仍定位到相应题。用户要求时补配图方向/图源入口。需要表格时保留四个完整字段，摘要仍是一段。链接统一为 `[来源名·文章标题](https://...)`，标注支持什么论据。旅行可补地点，明星可补案例，避免额外的大量流程字段淹没成品。

### 7. 交付前自检

普通选题核对数量、四项完整性、字符数、疑问号、对象与单一钩子、标题是否吸睛而非说明标签、论据与链接对应、配图可行性、时效/季节、概念去重、品类合规、日本元素排除以及真实核验状态。图片交付或制作阶段再增加逐张图文一致、尺寸与授权核查。

若输出结构化 JSON，可运行 `python scripts/validate_topics.py <选题.json>` 检查字段、长度、URL形态、案例数及部分状态冲突；脚本不能判断语句是否为疑问句、事实真假、来源可信、授权或语义重复。这些必须人工核查。没有 JSON 时直接检查题卡，不强制为运行脚本额外生成文件。

交付如有缺项，把缺口落到具体题目；满足数量确实困难时说明已完成多少、哪些被淘汰及原因。不称未完成核验的内容为“主推”“可上架”；“待排期草案”也不代表所有核验通过。
